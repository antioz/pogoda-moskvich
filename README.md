# Погода для москвичей

Telegram-бот, который раз в день постит прогноз погоды по Москве в канал — но не сухими цифрами, а голосом уставшего москвича: «блиииин жарко жесть +30», «блиин опять дождь +14», «блиииин похоолодало +6».

## Как работает

```
GitHub Actions (cron, 07:00 МСК)
        │
        ▼
   node bot.js
        │
        ├─ src/weather.js   → Open-Meteo API (без ключа), погода по Москве
        ├─ src/phrases.js   → превращает погоду в настроенческую фразу
        └─ src/telegram.js  → шлёт пост в канал через Bot API
```

Сервер не нужен: скрипт просыпается раз в день по расписанию, делает один пост и засыпает.

## Источник данных

[Open-Meteo](https://open-meteo.com) — бесплатно, без регистрации и API-ключа. Берётся дневной максимум температуры, WMO weather_code и облачность для координат Москвы (55.7558, 37.6173).

## Логика фраз

`src/phrases.js` сначала смотрит на тип погоды по приоритету (гроза → снег → гололёд → дождь → туман), и только если осадков нет — выбирает категорию по дневной температуре (пекло 30+, жара 25+, тепло, прохлада, похолодание, мороз, дубак). Внутри категории фраза берётся случайно, чтобы канал не повторялся.

Расширить тексты — просто добавить строки в нужный массив `pick([...])`.

## Локальный запуск

```bash
# прогон без отправки — просто покажет погоду и фразу
node bot.js --dry-run

# реальная отправка (нужны переменные окружения)
cp .env.example .env   # заполнить BOT_TOKEN и CHANNEL_ID
export $(cat .env | xargs) && node bot.js
```

## Деплой (GitHub Actions)

1. Создать Telegram-канал, добавить бота **администратором** (с правом публикации).
2. В репозитории: **Settings → Secrets and variables → Actions → New repository secret**:
   - `BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather)
   - `CHANNEL_ID` — `@username` публичного канала или числовой `chat_id` приватного
3. Workflow `.github/workflows/daily.yml` запускается сам в 07:00 МСК. Проверить вручную: вкладка **Actions → Ежедневный прогноз → Run workflow**.

## Изменить время поста

В `.github/workflows/daily.yml` поле `cron` (время в **UTC**). `0 4 * * *` = 07:00 МСК. Для 09:00 МСК → `0 6 * * *`.
