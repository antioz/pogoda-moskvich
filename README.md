# Погода для москвичей

Telegram-бот [@mscwthr_bot](https://t.me/mscwthr_bot), который раз в день постит прогноз по Москве голосом уставшего москвича: «блиииин жарко жесть +30», «блиин опять дождь +14», «блиииин похоолодало +6».

**Саморегистрирующийся**: любой пользователь добавляет бота в любую группу/канал (или жмёт `/start` в личке) — и тот сам начинает слать туда погоду. Без участия владельца.

## Как работает

```
                 ┌─ poll.yml (каждые ~5 мин) ─ node src/poll.js
                 │     getUpdates → ловит «бота добавили» → пишет chat_id
GitHub Actions ──┤                                          в data/state.json
                 │
                 └─ daily.yml (07:00 МСК) ──── node bot.js
                       Open-Meteo → фраза → рассылка во ВСЕ чаты из state.json
```

Сервера нет: всё крутится на бесплатном GitHub Actions, состояние хранится в `data/state.json` прямо в репозитории (Actions коммитит его обратно).

### Компоненты

| Файл | Назначение |
|---|---|
| `src/weather.js` | погода по Москве из [Open-Meteo](https://open-meteo.com) (без API-ключа) |
| `src/phrases.js` | генератор «блиииин»-фразы по WMO-коду и температуре (14 веток) |
| `src/poll.js` | слушатель: регистрирует/удаляет чаты, шлёт новичку приветствие + погоду |
| `src/telegram.js` | отправка через Bot API |
| `src/store.js` | чтение/запись `data/state.json` |
| `bot.js` | ежедневная рассылка во все чаты + чистка отвалившихся |

### Состояние (`data/state.json`)

```json
{
  "offset": 123,                       // курсор getUpdates
  "lastRun": "2026-06-12T04:00:00Z",   // heartbeat последней рассылки
  "chats": {
    "-1001234567890": { "title": "Чат друзей", "type": "supergroup", "addedAt": "..." }
  }
}
```

`offset` — позиция в очереди апдейтов Telegram, чтобы не обрабатывать одно и то же дважды. Чат с положительным id — личка, с отрицательным — группа/канал.

## Что нужно для работы

1. Секрет `BOT_TOKEN` в **Settings → Secrets and variables → Actions** (уже установлен).
2. В [@BotFather](https://t.me/BotFather) у бота включено **Allow Groups** (по умолчанию включено) — иначе его нельзя добавить в группы.
3. Для постинга в **канал** бота надо сделать админом канала (право «Публикация сообщений»). В **группу** — достаточно добавить обычным участником.

Дальше — ничего. Любой добавляет бота куда угодно, в течение ~5–15 минут слушатель его регистрирует (и сразу шлёт приветствие с текущей погодой), а в 07:00 МСК идёт ежедневная рассылка.

## Логика фраз

`src/phrases.js` сначала смотрит тип погоды по приоритету (гроза → снег → гололёд → дождь → туман), без осадков — выбирает категорию по дневной температуре (пекло 30+, жара 25+, тепло, прохлада, похолодание, мороз, дубак). Внутри категории фраза случайна. Расширить — добавить строки в нужный `pick([...])`.

## Локальный запуск

```bash
export BOT_TOKEN=...     # токен от @BotFather
node bot.js --dry-run    # показать погоду и пример фразы, без отправки
node src/poll.js         # один опрос Telegram
node bot.js              # реальная рассылка во все чаты из state.json
```

## Изменить время поста

`.github/workflows/daily.yml`, поле `cron` (время в **UTC**). `0 4 * * *` = 07:00 МСК; для 09:00 МСК → `0 6 * * *`.

## Ограничения

- GitHub Actions cron неточный: регистрация нового чата может занять до ~15 минут. Для ежедневной погоды некритично.
- Рассылка без батчинга, троттлинг 50 мс/сообщение. При тысячах чатов стоит перейти на webhook (Cloudflare Workers / Vercel).
